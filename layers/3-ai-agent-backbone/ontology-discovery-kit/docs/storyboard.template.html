Explainer

Six agents, one deterministic pipeline, named human approvers

The four persona agents come from the playbook's BA, EA, DA and Engineering roles. Two more do the working-group jobs: the Ontology Steward and the Conformance agent. Agents only ever recommend. Merging, grading and gate checks are deterministic code, so results can be repeated and audited. Approval stays with the people named in the playbook's decision-rights table.

Export

Run it for real in another Claude Code

The kit is self-contained. It is a folder with the playbook as config, six subagent definitions, an orchestration skill, the deterministic pipeline and tests. It needs Python 3.10+ and PyYAML. It doesn't need Docker or an API key, because Claude Code is the LLM for the live agents.

Copy the kit

Copy layers/3-ai-agent-backbone/ontology-discovery-kit/ to the root of a new or existing repository, or open the folder itself as the project. Its .claude/ folder must be at the project root so the agents and skill load.

Check it works

pip install -r requirements.txt python -m unittest discover -s tests python -m ontokit simulate

Add your evidence

Create discovery/inputs/loop-01/ (or replace the sample) with your document extracts and example code. List every file in manifest.yaml with its provenance, date and, where known, the system it came from. Images of diagrams are fine: the orchestrator transcribes them to Mermaid first.

Start the live loop

Paste this into Claude Code in that project:

Run the ontology discovery loop for loop-01 following .claude/skills/ontology-discovery-loop/SKILL.md. Use the ea-agent, ba-agent, da-agent and eng-agent subagents in parallel, validate their proposals, run the pipeline, then the ontology-steward and conformance-agent reviews. Stop at the human gate and ask me for decisions one approver role at a time. Do not fill in any decision I have not given.

Answer, add evidence, repeat

Send the unknowns register to the named owners. Put their answers and any new code context (schemas, data samples, real source) into loop-02 and run again. Grades move up, contradictions get resolved, and stand-ins get replaced with real adapters. Rebuild this page from any run with python tools/build_storyboard.py --loop loop-02.

What the simulation does not show: how well the live agents read messy real documents. The rule-based stand-in agents only find what is written in recognisable patterns. Expect the live agents to find more, and the validator to reject some of their proposals on the first pass. That rejection loop is intentional.
