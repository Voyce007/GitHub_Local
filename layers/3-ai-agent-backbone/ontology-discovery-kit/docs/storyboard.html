Explainer

Six agents, one deterministic pipeline, named human approvers

The four persona agents come from the playbook's BA, EA, DA and Engineering roles. Two more do the working-group jobs: the Ontology Steward and the Conformance agent. Agents only ever recommend. Merging, grading, gate checks and the change register are deterministic code, so they can be repeated and audited. Approval stays with the people the playbook names.

Run it for real in another Claude Code

The kit is self-contained. It is a folder with the playbook as config, six subagent definitions, an orchestration skill, the deterministic pipeline and tests. It needs Python 3.10+ and PyYAML. It doesn't need Docker or an API key, because Claude Code is the LLM for the live agents.

Copy the kit

Copy layers/3-ai-agent-backbone/ontology-discovery-kit/ to the root of a repository, or open the folder itself as the project. Its .claude/ folder must be at the project root so the agents and skill load.

Check it works

pip install -r requirements.txt python -m unittest discover -s tests python -m ontokit simulate --loop loop-01 python -m ontokit simulate --loop loop-02 # iterates on loop-01

Add your first evidence batch

Replace discovery/inputs/loop-01/ with your document extracts and example code. List every file in manifest.yaml with its provenance, date and, where known, the system it came from. Diagrams that are only images get transcribed to Mermaid by the orchestrator.

Start the live loop

Paste this into Claude Code in that project:

Run the ontology discovery loop for loop-01 following .claude/skills/ontology-discovery-loop/SKILL.md. Use the ea-agent, ba-agent, da-agent and eng-agent subagents in parallel, validate their proposals, run the pipeline, then the ontology-steward and conformance-agent reviews. Stop at the human gate and ask me for decisions one approver role at a time. Do not fill in any decision I have not given.

Iterate: loop 2, 3, …

Create discovery/inputs/loop-02/ with carry_forward: [loop-01] in its manifest. Add the SME answers (provenance sme-answer) and any new code context: schema exports, real source, data samples. Then ask Claude Code to "run the discovery loop for loop-02". Element ids stay stable, contradictions are resolved by authority, unchanged human decisions carry forward, and a change register shows what moved. Rebuild this page with python tools/build_storyboard.py.

What the simulation does not show: how well the live agents read messy real documents. The rule-based stand-in agents only find what is written in recognisable patterns. Expect the live agents to find more, and the validator to send some of their proposals back on the first pass. That rejection loop is intentional.
